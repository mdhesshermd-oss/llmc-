# Инструкция по сборке refactored проекта

Для сборки переписанного кода чита (loader и logic) вам потребуется окружение Windows и компилятор MSVC.

## Требования
1. **Microsoft Visual Studio** (2019 или 2022) с установленным компонентом "Desktop development with C++".
2. **Windows SDK** (устанавливается вместе с Visual Studio).
3. **Архитектура x64** (DayZ и игровые движки Enfusion работают только на x64).

## Сборка компонентов

### 1. Сборка Логики (refactored_logic.c)
Этот файл содержит ядро ESP. Его лучше всего собирать как часть динамической библиотеки (DLL), которая будет внедряться в игру.

Пример команды для компиляции через `cl.exe` (в Visual Studio Native Tools Command Prompt):
```bash
cl.exe /LD /O2 /arch:AVX2 refactored_logic.c /Fe:cheat_core.dll
```
*   `/LD` — создать DLL.
*   `/O2` — максимальная оптимизация скорости.
*   `/arch:AVX2` — включить поддержку современных инструкций (необходимо для SIMD кода).

### 2. Сборка Лоадера (refactored_loader.c)
Лоадер можно собрать как отдельный исполняемый файл (.exe), который будет распаковывать и запускать основной чит.

Пример команды:
```bash
cl.exe /O2 refactored_loader.c /link /OUT:loader.exe
```

## Интеграция
Поскольку оригинальный проект был основан на **Tauri**, для полной сборки "с интерфейсом" вам потребуется:
1. Установить **Rust** и **Node.js**.
2. Создать новый Tauri проект.
3. Подключить `refactored_logic.c` как нативный модуль через `cc` crate в Rust.
4. Вызывать функции из `refactored_logic.c` через Tauri `command`.

## Важные замечания
- Код содержит заглушки для адресов функций игрового движка (например, `0x7FFFB4492770`). Для работы на актуальной версии DayZ эти адреса (оффсеты) нужно обновить с помощью ReClass.NET или IDA Pro.
- Для полноценной работы `refactored_loader.c` требует наличия сжатого бинарного файла чита в ресурсах или в секции данных.
