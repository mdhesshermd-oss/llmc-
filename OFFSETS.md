# Руководство по безопасности и обновлению оффсетов

Для предотвращения бана при обновлении DayZ реализована система автоматического поиска (Pattern Scanning) и проверки валидности данных (Sanity Checks).

## 1. Использование сигнатур (AOB)
Вместо фиксированных оффсетов для базовых указателей (например, `World`), чит ищет уникальные последовательности байт в коде игры.

- **Как создать новую сигнатуру:**
    1. Откройте `DayZ.exe` в IDA Pro.
    2. Перейдите по старому адресу `World` (если он еще работает) или найдите функцию, которая его использует.
    3. Выделите несколько инструкций вокруг обращения к `World`. Пример: `mov rax, [rip + 0xXXXX]`.
    4. Создайте маску, заменив меняющиеся байты (смещения) на `?`.
    5. Обновите константу `SIG_WORLD` в файле `refactored_logic.cpp`.

## 2. Список актуальных оффсетов (Enfusion Engine)
Ниже приведены оффсеты, восстановленные из дампа памяти и подтвержденные анализом.

| Имя | Оффсет | Описание |
| :--- | :--- | :--- |
| `World` | `SIG_WORLD` | Указатель на GameWorld |
| `ViewMatrix` | `0x1B0` | Матрица камеры |
| `EntityList` | `0x1E88` | Таблица всех сущностей |
| `EntityCount` | `0x1E90` | Количество сущностей |
| `PlayerType` | `0x158` | 0x1 = Survivor (Игрок) |
| `Coordinates` | `0x2C0` | Вектор 3D позиции |
| `CameraPos` | `0x28` | Позиция локальной камеры |

## 3. Проверка валидности (Sanity Checks)
Чит постоянно проверяет данные, которые он читает из памяти игры. Если данные выглядят подозрительно, модуль ESP автоматически отключается (`Emergency Shutdown`), чтобы BattlEye не зафиксировал чтение некорректных или защищенных областей памяти.

**Признаки сбоя оффсетов:**
- Количество сущностей (`entity_count`) более 5000.
- `type_id` игрока имеет нереалистичное значение (больше 100).
- Координаты игрока принимают значения `NaN` или `Infinity`.

Если вы видите, что ESP перестал работать после обновления игры, это сработала защита. Вам необходимо найти новые сигнатуры и оффсеты.

## 3. Рекомендации по безопасности
1. Всегда тестируйте новые оффсеты на тестовом аккаунте.
2. Если сигнатура `SIG_WORLD` перестала находиться, не пытайтесь использовать старый жестко заданный оффсет.
3. Используйте ReClass.NET для проверки, что структура `Entity` не изменилась (оффсеты `OFFSET_PLAYER_POS` и `OFFSET_TYPE_ID`).
