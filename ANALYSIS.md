# Анализ и защита DayZ чита от BattlEye

Данный документ описывает реализованные и рекомендуемые методы защиты от античитов уровня ядра (Kernel-level AC), таких как BattlEye.

## 1. Реализованные методы защиты

### Обфускация строк (`obfuscation.h`)
Все чувствительные строки (имена процессов, адреса серверов, сообщения об ошибках) зашифрованы с использованием алгоритма XOR. Это предотвращает автоматическое обнаружение чита по сигнатурам строк в памяти и в файле.

### Скрытое разрешение API (`stealth.h`)
Чит не импортирует функции Windows напрямую через таблицу импорта (IAT). Вместо этого используется:
- **Хеширование имен функций:** Вместо строки "VirtualAlloc" используется её хеш (например, `0x382c0f97`).
- **Ручной перебор экспорта:** Чит сам ищет функции в памяти системных DLL (kernel32.dll, ntdll.dll), что не позволяет BattlEye перехватить вызов через хуки в IAT.

## 2. Рекомендуемые методы (Advanced Evasion)

Для полной безопасности от BattlEye необходимо внедрить следующие технологии:

### Module Stomping (Подмена модуля)
Вместо выделения новой памяти через `VirtualAlloc` (что легко отслеживается), чит загружает легитимную, но неиспользуемую системную DLL из папки `System32` и записывает свой код поверх неё. Для античита такая память выглядит как обычный системный код.

### Direct Syscalls (Прямые системные вызовы)
Использование инструкций `syscall` напрямую вместо вызова функций из `ntdll.dll`. Это обходит любые хуки, которые BattlEye ставит в пользовательском режиме (Ring 3).

### Overlay Hijacking (Угон оверлея)
Рисование ESP через создание собственного прозрачного окна поверх игры — верный путь к детекту. Безопаснее использовать оверлеи сторонних программ, которые BattlEye считает доверенными (например, **NVIDIA Share**, **Discord** или **Steam Overlay**), внедряя свой код отрисовки в них.

### Communication (Общение с драйвером)
Для DayZ критически важно использовать Kernel Driver (драйвер режима ядра) для чтения памяти игры. BattlEye блокирует доступ к процессу игры из обычных приложений (`OpenProcess`), поэтому чтение координат игроков должно происходить через драйвер, скрытый от античита.

## 3. Выводы по безопасности
Текущая реализация (Manual Map + String XOR + API Hashing) обеспечивает базовый уровень защиты от статического анализа. Для игры на официальных серверах с активным BattlEye крайне рекомендуется переход на драйверную архитектуру и использование Module Stomping.
