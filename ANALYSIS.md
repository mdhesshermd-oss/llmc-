# DayZ Stealth Cheat: Анализ Архитектуры и Сравнение Гипервизоров (v8 Final)

Этот документ представляет собой итоговый отчет по архитектуре проекта и сравнительный анализ с популярными открытыми решениями (`illusion-rs` и `gbhv`).

## 1. Сравнительный анализ: Почему текущая реализация лучше для вас?

Мы проанализировали два продвинутых проекта гипервизоров, на которые вы ссылались, и сопоставили их с вашей задачей (чит для DayZ на процессоре AMD Ryzen 5 7535HS).

| Характеристика | illusion-rs (Rust) | gbhv (C) | Текущий проект (C++ Combat-Ready) |
| :--- | :--- | :--- | :--- |
| **Поддержка AMD** | ❌ Нет | ❌ Нет | ✅ **Полная (SVM + NPT)** |
| **Тип Гипервизора** | Type-1 (UEFI) | Type-2 (Driver) | **Type-2 -> Ring -1 (Driverless)** |
| **Скрытность памяти** | EPT Shadowing | EPT Hooking | **NPT Cloaking (Shadow Pages)** |

| **Игровая логика** | Нет | Нет | ✅ **DayZ ESP (из дампа)** |

### Выводы анализа:
1. **Проблема совместимости**: И `illusion-rs`, и `gbhv` разработаны исключительно под Intel VT-x. На вашем процессоре AMD они **не запустятся** и приведут к критической ошибке системы.
2. **Уровень скрытности**: `gbhv` остается в системе как видимый драйвер. Наша реализация использует драйвер только как временный мост для перехода в Ring -1, после чего он может быть полностью удален из памяти.
3. **Готовность "из коробки"**: Наш проект уже содержит отрефакторенную логику DayZ, Page Table Walker для AMD и систему инъекции через Thread Hijacking, что избавляет вас от месяцев низкоуровневой разработки.

## 2. Ключевые механизмы (Combat-Ready v8)

### NPT Cloaking (Технология "Призрак")
Мы внедрили лучшее из концепций `gbhv` и `illusion-rs`, адаптировав их под AMD:
- **ID-Fetch Fault**: Гипервизор ловит попытку процессора выполнить код. Если это код чита — подменяется физическая страница.
- **Data Access**: Если античит (BattlEye) пытается прочитать эту же область памяти — гипервизор мгновенно подменяет её на оригинальную "чистую" страницу игры.

### Защита от обнаружения по таймингам
Вдохновившись `illusion-rs`, мы добавили:
- **TSC Jitter/Correction**: При каждом VM-Exit (выходе в гипервизор) происходит коррекция счетчика тактов процессора, чтобы античит не увидел микро-задержки, характерные для работы виртуализации.

## 3. Инъекция: Thread Hijacking vs CreateRemoteThread
Большинство открытых мапперов используют `CreateRemoteThread`, что является "черной меткой" для BattlEye.
Наша система:
1. Находит поток отрисовки игры.
2. Приостанавливает его.
3. Подменяет регистр `RIP` на наш зашифрованный шеллкод.
4. Выполняет инициализацию и возвращает поток в исходное состояние.
Это выглядит для системы как легитимное выполнение игрового кода.

## 4. Безопасность данных
- **AES-128 CBC**: Вся логика чита зашифрована.
- **CryptoAPI**: Используется стандартный провайдер Windows для дешифровки, что не вызывает подозрений у проактивной защиты.
- **Key Wiping**: Ключ дешифровки и секретный ключ гипервызовов уничтожаются в памяти сразу после использования.
