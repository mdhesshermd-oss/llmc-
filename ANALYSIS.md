# Анализ кода чита DayZ: Лоадер и ESP

Данный документ описывает работу загрузчика (loader) и модуля ESP, адаптированного исключительно для отображения игроков.

## 1. Загрузчик (Loader) - `start`
Функция `start` реализует алгоритм **Manual Map Injection** (ручное отображение DLL в память).

- **Распаковка (Decompression):** Основная часть кода `start` (от LABEL_24 до LABEL_121) — это реализация LZMA-подобного декодера. Он распаковывает сжатый образ чита, хранящийся прямо внутри исполняемого файла, в новую область памяти.
- **Релокация (Relocation):** После распаковки цикл в районе LABEL_127 корректирует адреса (Base Relocation), чтобы код мог корректно выполняться по новому базовому адресу.
- **Импорты (Imports):** В конце функции происходит динамическое разрешение системных функций (LoadLibrary/GetProcAddress) для загрузки необходимых зависимостей.
- **Вход в чит:** После подготовки памяти лоадер вызывает TLS-коллбэки и переходит на точку входа (Entry Point) распакованного чита.

## 2. Модуль ESP для Игроков - `PlayerOnlyESPUpdate`
Логика отрисовки была переработана для поддержки только человеческих персонажей.

- **Фильтрация сущностей:** В оригинале чит обрабатывал все объекты. В рефакторинге добавлена проверка `entData.type_id == 0x1`. Это гарантирует, что ресурсы процессора тратятся только на обработку игроков, игнорируя зомби и предметы.
- **SIMD Оптимизация:** Чит использует наборы инструкций SSE/AVX для пакетной обработки указателей на сущности. Это позволяет поддерживать высокий FPS даже на серверах с большим количеством игроков.
- **Интеграция с движком:** Чит напрямую взаимодействует с функциями движка Enfusion (DayZ) для проверки видимости и получения актуальных координат костей игрока.

## 3. Файлы рефакторинга
- `refactored_loader.c`: Читаемая версия процесса распаковки и маппинга.
- `refactored_logic.c`: Код ESP с фильтрацией по игрокам.
