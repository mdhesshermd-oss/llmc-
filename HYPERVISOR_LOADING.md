# Руководство по загрузке гипервизора (VMM) в систему

Для работы чита через гипервизор (Ring -1), сам гипервизор должен быть загружен в систему раньше античита или скрытно во время работы Windows. Существует два основных метода загрузки.

---

## Метод 1: Загрузка через UEFI Bootloader (Самый безопасный)
Этот метод подразумевает запуск гипервизора до загрузки самой Windows. Это делает гипервизор "хозяином" системы, и Windows запускается уже как гостевая ОС.

### Шаги реализации:
1. **Подготовка:** Создайте EFI-приложение (например, на базе `EDK II`).
2. **Инициализация:**
   - Проверьте поддержку VMX (`CPUID`).
   - Выделите память для структур управления (VMCS, VMXON, EPT Tables).
3. **Захват управления:**
   - Настройте обработчики прерываний (VM-Exit handlers).
   - Выполните инструкцию `VMLAUNCH`.
4. **Загрузка ОС:** Гипервизор вызывает стандартный загрузчик Windows (`bootmgfw.efi`).

**Плюс:** BattlEye не может просканировать гипервизор, так как он загружен до него и контролирует все обращения к физической памяти.

---

## Метод 2: "Runtime" загрузка через драйвер (System Driver)
Гипервизор загружается как обычный драйвер ядра Windows, а затем "виртуализирует" текущую работающую систему (метод Blue Pill).

### Шаги реализации:
1. **Драйвер:** Создайте драйвер ядра (.sys).
2. **Отключение защит:** Временно отключите `PG` (PatchGuard), если планируете изменять структуры ядра.
3. **Инициализация VMX:**
   - Настройте VMCS для каждого логического ядра процессора.
   - Настройте EPT (Extended Page Tables) для прозрачного маппинга памяти.
4. **Виртуализация:** Вызовите функцию, которая выполняет `VMLAUNCH` на всех ядрах. После этого текущая сессия Windows становится "гостем".

**Плюс:** Не требует перезагрузки и манипуляций с EFI-разделом диска.

---

## Настройка обработчика VMCALL
Для того чтобы ваш чит (Refactored Loader) мог общаться с гипервизором, в коде VMM должен быть реализован обработчик VM-Exit по причине `EXIT_REASON_VMCALL`.

Пример логики в гипервизоре (C):
```c
void HandleVmCall(PGUEST_REGISTERS Registers) {
    if (Registers->Rcx == HV_SECRET_KEY) {
        switch (Registers->Rdx) {
            case HV_IO_READ_PHYSICAL:
                // Выполнить чтение физической памяти и вернуть результат в регистры гостя
                break;
            case HV_IO_GET_CR3:
                // Найти структуру EPROCESS и вернуть DirectoryTableBase
                break;
        }
    }
}
```

## Итог
Для полноценной работы системы вам необходимо использовать готовый проект гипервизора (например, **HyperBone**, **SimpleVisor** или **DarthVisor**) и интегрировать в его обработчик `VMCALL` команды, описанные в нашем файле `hypervisor_io.h`.
